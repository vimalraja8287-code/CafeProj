Chapter 01 — Level: Beginner

JSX — Writing HTML Inside JavaScript

Beginner
🖊️
What is JSX?
Syntax extension that looks like HTML but compiles to JavaScript
Definition

JSX (JavaScript XML) is a syntax that lets you write HTML-like code directly inside JavaScript. React components return JSX. Vite (via Babel/esbuild) converts JSX into React.createElement() calls behind the scenes. Every opening tag must be closed, you use className instead of class, and JavaScript expressions go inside { } curly braces.

src/components/common/Toast.jsx — simple JSX component
Toast.jsx JSX 
// JSX lets us mix HTML structure with JavaScript logic
export function Toast() {
  const toast = { type: 'success', message: 'Order Placed!' };

  return (
    <div          // ← JSX element (looks like HTML)
      style={{     // ← double {{ }} for JS object inside JSX
        position: 'fixed',
        bottom: '24px',
        right: '24px',
        backgroundColor: '#FFFFFF',
        borderRadius: '12px',
        padding: '12px 18px',
      }}
    >
      {/* ← JSX comment */}
      <span>{toast.message}</span>  // ← JS expression in { }
    </div>
  );
}

🔑 Key Takeaways
  • JSX must return ONE root element — wrap siblings in <></> (Fragment)
  • Use className not class — it's JavaScript
  • Inline styles are JavaScript objects: style={{ color: 'red' }}
  • Embed any JavaScript expression inside { }
  • JSX is NOT required but it makes React much easier to read

React Components — Functions That Return UI

Beginner
🧩
Function Components
The fundamental building block of every React application
Definition

A React Component is a JavaScript function that returns JSX. Components let you split the UI into independent, reusable pieces. Each component has its own logic and appearance. Component names must start with a capital letter so React can distinguish them from regular HTML tags. In SpideyCafe, we have 29+ components, from tiny VegBadge to the full CheckoutPage.

Chapter 03 — Level: Beginner

Props — Passing Data Between Components

Beginner
📦
Props (Properties)
The way parent components send data down to child components
Definition

Props (short for properties) are the arguments you pass to a React component — like function parameters. Props flow one way: from parent → child. A child component cannot modify its own props; props are read-only. In SpideyCafe, MenuItemCard receives the menu item object as a prop, ConfirmModal receives isOpen, title, message, and callback functions as props.

src/components/common/ConfirmModal.jsx — excellent props example with defaults
ConfirmModal.jsx — Props with default values JSX 
// Props are destructured from the function parameter
export function ConfirmModal({
  isOpen,                        // ← boolean prop
  title = 'Confirm Action',     // ← prop with DEFAULT value
  message,                       // ← string prop
  confirmLabel = 'Confirm',     // ← default label
  cancelLabel = 'Cancel',       // ← default label
  isDanger = false,            // ← boolean with default
  onConfirm,                     // ← function prop (callback)
  onCancel,                      // ← function prop (callback)
}) {
  if (!isOpen) return null;  // ← prop controls visibility

  return (
    <div  {/* modal overlay */}>
      <h3>{title}</h3>                {/* use the prop */}
      <p>{message}</p>

      <button
        onClick={onConfirm}             {/* call the function prop */}
        style={{
          backgroundColor: isDanger ? '#DC2626' : 'var(--brand-terracotta)',
        }}
      >
        {confirmLabel}
      </button>

      <button onClick={onCancel}>{cancelLabel}</button>
    </div>
  );
}

  • Props are read-only — never mutate them inside a child component

  • Use children prop to nest JSX content inside a component

Chapter 04 — Level: Intermediate

useState Hook — Managing Component State

Intermediate
🔄
useState
Gives your component memory — data that changes and triggers re-renders
Definition

useState is a React Hook that lets your component remember values between renders. When state changes, React re-renders (re-runs) the component so the UI reflects the latest data. It returns a pair: [currentValue, setterFunction]. You never directly mutate state — always use the setter. SpideyCafe uses useState extensively: for cart items, search terms, active category, form fields, modal open/close, etc.

src/pages/MenuPage.jsx — multiple useState in one component
MenuPage.jsx — useState examples JSX 
import React, { useState, useEffect } from 'react';

export function MenuPage() {
  // [currentValue, setterFunction] = useState(initialValue)

  const [menuItems, setMenuItems]           = useState([]);
  //    ↑ array of menu items    ↑ function to update it   ↑ starts empty

  const [loading, setLoading]               = useState(true);
  //    ↑ boolean                                          ↑ starts true

  const [activeCategory, setActiveCategory] = useState('all');
  //    ↑ selected category tab                           ↑ starts 'all'

  const [searchTerm, setSearchTerm]         = useState('');
  //    ↑ what user typed in search box                   ↑ starts empty

  // When user clicks a category button, we call the setter:
  // setActiveCategory('coffees')  ← this triggers a re-render

  // Derived state — computed from existing state (no useState needed)
  const filteredItems = menuItems.filter((item) => {
    const matchesCategory = activeCategory === 'all' || item.category === activeCategory;
    const matchesSearch   = item.name.toLowerCase().includes(searchTerm.toLowerCase());
    return matchesCategory && matchesSearch;
  });

  return (
    <div>
      {/* Pass state down as props */}
      <SearchBar
        searchTerm={searchTerm}
        setSearchTerm={setSearchTerm}    {/* pass setter as prop */}
      />
      <CategoryFilter
        activeCategory={activeCategory}
        onSelectCategory={setActiveCategory}  {/* setter as callback prop */}
      />
    </div>
  );
}

Functional Updater Pattern (Advanced useState)

src/context/OrderContext.jsx — functional updater for cart
OrderContext.jsx — functional state update JS 
// ✅ CORRECT — use functional updater when new state depends on old state
const addToCart = (item, qty = 1) => {
  setCartItems((prev) => {       // ← prev is the current state
    const existingIndex = prev.findIndex((i) => i.id === item.id);
    if (existingIndex > -1) {
      // Item already in cart — increase quantity
      const updated = [...prev];    // spread to copy array (never mutate!)
      updated[existingIndex] = {
        ...updated[existingIndex],  // spread to copy object
        quantity: updated[existingIndex].quantity + qty,
      };
      return updated;
    } else {
      // New item — add to end
      return [...prev, { ...item, quantity: qty }];
    }
  });
};
⚠️ Never mutate state directly!
cartItems.push(item) — ❌ WRONG (React won't see the change)
setCartItems([...cartItems, item]) — ✅ CORRECT (creates a new array)

Chapter 05 — Level: Intermediate

useEffect Hook — Side Effects & Lifecycle

Intermediate
⚡
useEffect
Run code after render — for API calls, timers, localStorage, subscriptions
Definition

useEffect is a Hook that lets you perform side effects in a component — actions that happen outside of rendering: fetching data from an API, saving to localStorage, setting timers, subscribing to events. It runs after every render by default. The dependency array [] controls when it re-runs. SpideyCafe uses useEffect to load menu items on mount, save the cart to localStorage when it changes, and auto-dismiss toast notifications.

The 3 Forms of useEffect

SyntaxWhen it runsSpideyCafe Example
useEffect(fn)After EVERY renderRarely used (performance issue)
useEffect(fn, [])Only ONCE on mountLoad menu items
useEffect(fn, [dep])When dep changesSave cart when cartItems changes
src/pages/MenuPage.jsx — useEffect to load menu on mount
MenuPage.jsx — Data fetching with useEffect JS 
import React, { useState, useEffect } from 'react';

export function MenuPage() {
  const [menuItems, setMenuItems] = useState([]);
  const [loading, setLoading]     = useState(true);

  useEffect(() => {
    // ↑ This runs ONCE after component mounts (appears on screen)

    let isMounted = true;  // ← flag to prevent state update on unmounted component

    async function loadMenu() {
      try {
        setLoading(true);
        const data = await getMenuItems();  // ← async API call
        if (isMounted) {                      // ← only update if still mounted
          setMenuItems(data);
        }
      } catch (err) {
        console.error('Failed to load menu:', err);
      } finally {
        if (isMounted) setLoading(false);
      }
    }

    loadMenu();                              // ← call the async function

    // CLEANUP function — runs when component unmounts
    return () => {
      isMounted = false;                    // ← prevent memory leak
    };
  }, []);  // ← empty array = run only ONCE on mount
}
src/context/OrderContext.jsx — useEffect with dependency
OrderContext.jsx — useEffect syncing cart to localStorage JS 
// Run this effect every time cartItems changes
useEffect(() => {
  setStoredItem(STORAGE_KEYS.CART, cartItems);  // save to localStorage
}, [cartItems]);  // ← dependency array: re-run when cartItems changes

// Auto-dismiss toast after 4 seconds
const showToast = (message, type = 'info') => {
  const id = Date.now();
  setToast({ id, message, type });

  setTimeout(() => {          // ← side effect: timer
    setToast((prev) =>        // ← functional update
      prev?.id === id ? null : prev
    );
  }, 4000);                   // ← dismiss after 4 seconds
};
💡 Pro Tip: Never put async directly on the useEffect callback. Instead, define an async function inside useEffect and call it — this is exactly the pattern used in MenuPage.jsx.

Chapter 06 — Level: Intermediate

Event Handling — Forms, Clicks & Input Control

Intermediate
🖱️
Event Handling & Controlled Inputs
Responding to user actions and managing form data with React state
Definition

In React, events like clicks, form submissions, and input changes are handled with camelCase event handlers like onClick, onSubmit, onChange. A Controlled Input means React state is the "single source of truth" for the input value — the input's value is bound to state, and onChange updates that state. This is how SpideyCafe's CheckoutPage manages the name, phone, and notes fields.

src/pages/CheckoutPage.jsx — full form with controlled inputs & validation
CheckoutPage.jsx — Controlled Form JSX 
export function CheckoutPage() {
  // State for each form field
  const [customerName, setCustomerName]   = useState('');
  const [customerPhone, setCustomerPhone] = useState('');
  const [specialNotes, setSpecialNotes]   = useState('');
  const [errors, setErrors]               = useState({});
  const [isSubmitting, setIsSubmitting]   = useState(false);

  // Form validation function
  const validateForm = () => {
    const errs = {};
    if (!customerName.trim()) {
      errs.customerName = 'Please enter your name.';
    }
    if (!customerPhone.trim() || customerPhone.trim().length < 8) {
      errs.customerPhone = 'Phone must be at least 8 digits.';
    }
    setErrors(errs);
    return Object.keys(errs).length === 0; // true = valid
  };

  // Form submit handler
  const handleSubmitOrder = async (e) => {
    e.preventDefault();      // ← prevent browser default page reload
    if (!validateForm()) return;  // ← stop if invalid

    try {
      setIsSubmitting(true);
      const newOrder = await placeOrder({ tableNumber, customerName, ... });
      navigate(`/order/${newOrder.id}`);  // ← redirect on success
    } finally {
      setIsSubmitting(false);
    }
  };

  return (
    <form onSubmit={handleSubmitOrder}>  {/* form submission event */}

      {/* Controlled text input */}
      <input
        type="text"
        value={customerName}                  {/* ← bound to state */}
        onChange={(e) => setCustomerName(e.target.value)}  {/* ← update state */}
        style={{
          border: errors.customerName ? '1.5px solid #DC2626' : '1.5px solid var(--border-color)',
        }}
      />

      {/* Show validation error */}
      {errors.customerName && (
        <span style={{ color: '#DC2626', fontSize: '0.8rem' }}>
          {errors.customerName}
        </span>
      )}

      {/* Disabled submit while loading */}
      <button
        type="submit"
        disabled={isSubmitting}                {/* ← prevent double-submit */}
        style={{ opacity: isSubmitting ? 0.7 : 1 }}
      >
        {isSubmitting ? 'Placing...' : 'Place Order'}
      </button>
    </form>
  );
}

Conditional Rendering — Showing Different UI

Intermediate
🔀
Conditional Rendering
React shows different UI based on state, props, or logic
Definition

Conditional Rendering means showing different UI components or elements based on a condition. In React, since JSX is just JavaScript, you use standard JavaScript conditionals: ternary operators ? :, short-circuit evaluation &&, or early returns from the function. SpideyCafe uses all three patterns extensively.

src/pages/MenuPage.jsx — three-way conditional rendering

{/* Three-way conditional: loading → empty → items */}

List Rendering — Arrays, .map() & Keys

Intermediate
📋
Rendering Lists with .map()
Transform arrays of data into arrays of UI elements
Definition

React renders lists by using JavaScript's .map() to transform an array of data into an array of JSX elements. The crucial rule: every list item needs a unique key prop so React can efficiently update only the changed items. Use a stable unique ID (like item.id) as the key — never use the array index as key if the list can be reordered.

src/pages/MenuPage.jsx — .map() over menu items array
MenuPage.jsx — List rendering with keys JSX 
{/* filteredItems is an array of menu item objects */}
{filteredItems.map((item) => (
  <MenuItemCard
    key={item.id}    {/* ← REQUIRED unique key — use item.id, not index */}
    item={item}      {/* ← pass whole item as prop */}
  />
))}

{/* CategoryFilter — mapping over CATEGORIES array */}
{CATEGORIES.map((cat) => (
  <button
    key={cat.id}               {/* ← unique key from data */}
    onClick={() => onSelectCategory(cat.id)}
    style={{
      backgroundColor: isActive ? 'var(--brand-terracotta)' : '#FFFFFF',
    }}

    {cat.name}

{/* order.items is an array of ordered menu items */}

Context API — Global State Without Prop Drilling

Advanced
🌐
React Context API
Share data across the whole component tree without passing props manually at every level
Definition

Context API solves prop drilling — the problem of passing props through many component layers just to reach a deeply nested child. With Context, you create a context, wrap your app in a Provider with a value, and any component anywhere in the tree can consume that value with useContext. SpideyCafe's OrderContext holds cart items, orders, toast notifications, and all their actions — shared across every page and component.

The 3-Step Pattern

src/context/OrderContext.jsx — the heart of SpideyCafe's state
OrderContext.jsx — Create, Provide, Consume JS 
import { createContext, useContext, useState, useEffect, useCallback } from 'react';

// ── STEP 1: CREATE the context ─────────────────────────────
const OrderContext = createContext(null);
// OrderContext is a special "container" for shared data

// ── STEP 2: CREATE the Provider component ─────────────────
export function OrderProvider({ children }) {
  // All the shared state lives HERE (in the provider)
  const [cartItems, setCartItems] = useState(() => {
    return getStoredItem(STORAGE_KEYS.CART, []);  // ← lazy initial state
  });
  const [orders, setOrders]           = useState([]);
  const [loadingOrders, setLoadingOrders] = useState(true);
  const [toast, setToast]             = useState(null);

  // ... all cart actions, order actions, toast helpers ...

  // The "value" object — everything consumers can access
  const value = {
    cartItems, cartTotals, addToCart, updateQuantity,
    removeFromCart, clearCart, getItemQuantity,
    orders, loadingOrders, refreshOrders,
    placeOrder, updateOrderStatus, simulateIncomingOrder,
    toast, showToast, hideToast,
  };

  // Wrap children in the Provider — they can now access "value"
  return <OrderContext.Provider value={value}>{children}</OrderContext.Provider>;
}

// ── STEP 3: CONSUME with a custom hook ────────────────────
export function useOrderContext() {
  const context = useContext(OrderContext);
  if (!context) {
    // Safety check — tell devs if they forgot to wrap with Provider
    throw new Error('useOrderContext must be used within an OrderProvider');
  }
  return context;
}

How Toast.jsx Consumes the Context

Toast.jsx — consuming context JSX 
import { useOrderContext } from '../../context/OrderContext';

export function Toast() {
  // Pull out exactly what we need from the context
  const { toast, hideToast } = useOrderContext();

  if (!toast) return null;  // no toast = render nothing

  return (
    <div>
      <span>{toast.message}</span>
      <button onClick={hideToast}>✕</button>

Custom Hooks — Extracting & Reusing Logic

Advanced
🪝
Custom React Hooks
Functions that start with "use" and encapsulate reusable stateful logic
Definition

A Custom Hook is a JavaScript function whose name starts with use and that calls other React hooks. Custom hooks let you extract stateful logic out of components so it can be reused across multiple components without duplicating code. SpideyCafe has 3 custom hooks: useCart, useOrders, and useTableNumber. Instead of calling useOrderContext everywhere, components call clean, purpose-specific hooks.

src/hooks/useTableNumber.js — most sophisticated custom hook in the project
useTableNumber.js — full custom hook JS 
import { useSearchParams } from 'react-router-dom';
import { getStoredItem, setStoredItem, STORAGE_KEYS } from '../services/storageService';

/**
 * Custom hook — starts with "use", uses other hooks inside
 * Manages which table number is active:
 * Priority: URL param → localStorage → default
 */
export function useTableNumber() {
  // Uses a React Router hook inside
  const [searchParams, setSearchParams] = useSearchParams();
  const rawTable = searchParams.get('table');  // reads ?table=3 from URL

  let activeTable = 1;  // default table

  if (rawTable) {
    const parsed = parseInt(rawTable, 10);
    if (!isNaN(parsed) && parsed > 0) {
      activeTable = parsed;
      setStoredItem(STORAGE_KEYS.TABLE, activeTable);  // save to localStorage
    }
  } else {
    const stored = getStoredItem(STORAGE_KEYS.TABLE, null);
    if (stored) activeTable = Number(stored);
  }

  const changeTable = (newTableNum) => {
    const num = Number(newTableNum);
    setStoredItem(STORAGE_KEYS.TABLE, num);
    setSearchParams((prev) => {
      const next = new URLSearchParams(prev);
      next.set('table', num.toString());
      return next;
    }, { replace: true });
  };

  // Return the interface — like a mini-API for the table
  return {
    tableNumber: activeTable,
    changeTable,
    availableTables: [1, 2, 3, 4, 5, 6],
    hasUrlTable: Boolean(rawTable),
  };
}

Chapter 12 — Level: Pro

useCallback — Stabilizing Functions for Performance

Pro
⚡
useCallback
Memoize functions so they don't get recreated on every render
Definition

useCallback returns a memoized (cached) version of a function. Without it, every time a component re-renders, every function defined inside is recreated — a new function reference. This matters when passing functions as props to child components, or as dependencies in useEffect. useCallback(fn, [deps]) only recreates the function when one of its dependencies changes. SpideyCafe's OrderContext wraps ALL its action functions in useCallback.

src/context/OrderContext.jsx — all functions wrapped in useCallback
OrderContext.jsx — useCallback patterns JS 
// Without useCallback — new function on EVERY render (bad for context consumers)
const showToastBAD = (message, type) => {  // ← recreated every render!
  setToast({ id: Date.now(), message, type });
};

// ✅ With useCallback — same function reference across renders
const showToast = useCallback((message, type = 'info') => {
  const id = Date.now();
  setToast({ id, message, type });
  setTimeout(() => {
    setToast((prev) => (prev?.id === id ? null : prev));
  }, 4000);
}, []);  // ← empty deps: never recreated (no dependencies)

// refreshOrders depends on nothing from outside
const refreshOrders = useCallback(async () => {
  try {
    setLoadingOrders(true);
    const data = await orderService.getOrders();
    setOrders(data);
  } catch (err) { console.error(err); }
  finally { setLoadingOrders(false); }
}, []);  // ← stable: never depends on any changing value

// placeOrder depends on: refreshOrders, clearCart, showToast
const placeOrder = useCallback(async (orderData) => {
  try {
    const newOrder = await orderService.createOrder(orderData);
    await refreshOrders();             // ← uses stable refreshOrders
    clearCart();
    showToast(`Order #${newOrder.id} placed!`, 'success');
    return newOrder;
  } catch (err) {
    showToast('Failed to place order.', 'warning');
    throw err;
  }
}, [refreshOrders, clearCart, showToast]);  // ← deps: recreate if these change
🔑 Key Takeaways
  • Every function in a component is recreated on re-render without useCallback
  • Use useCallback for functions passed as props to child components
  • Use useCallback for functions used as useEffect dependencies
  • The dependency array works the same as useEffect
  • Don't overuse it — premature optimization. Add it when you see performance issues

Service Layer & Async Data Fetching

Pro
🔌
Service Layer Architecture
Abstract all API/data operations behind service functions — separate concerns
Definition

A Service Layer separates data fetching logic from UI components. Instead of calling fetch('/api/menu') directly inside a component, you create dedicated service files (menuService.js, orderService.js) that encapsulate all data operations. SpideyCafe's service layer supports both mock data (for prototype) and real API calls (for production) controlled by a single flag API_CONFIG.USE_MOCK_DATA.

src/services/apiConfig.js + src/services/orderService.js
apiConfig.js + orderService.js — service pattern JS 
// ── apiConfig.js ─────────────────────────────────────────────
export const API_CONFIG = {
  USE_MOCK_DATA: true,   // ← flip to false for real backend
  API_BASE_URL: 'https://localhost:7001/api',
};

export async function apiFetch(endpoint, options = {}) {
  const url = `${API_CONFIG.API_BASE_URL}${endpoint}`;
  const response = await fetch(url, {
    ...options,
    headers: { 'Content-Type': 'application/json', ...options.headers },
  });
  if (!response.ok) {
    const err = await response.json().catch(() => ({ message: 'HTTP error' }));
    throw new Error(err.message);
  }
  return response.json();
}

// ── orderService.js ──────────────────────────────────────────
// Each function checks the flag — same interface for mock & real API

export async function getOrders() {
  if (!API_CONFIG.USE_MOCK_DATA) {
    return await apiFetch('/orders');  // ← real API call
  }
  // Prototype: read from localStorage
  await new Promise((resolve) => setTimeout(resolve, 100));  // simulate latency
  let orders = getStoredItem(STORAGE_KEYS.ORDERS, null);
  if (!orders) {
    orders = INITIAL_ORDERS;
    setStoredItem(STORAGE_KEYS.ORDERS, orders);
  }
  return orders;
}

export async function createOrder(orderPayload) {
  if (!API_CONFIG.USE_MOCK_DATA) {
    return await apiFetch('/orders', {
      method: 'POST',
      body: JSON.stringify(orderPayload),   // ← POST body
    });
  }
  // Prototype: create locally & save to localStorage
  const newOrder = {
    id: generateOrderId(),
    ...orderPayload,
    createdAt: new Date().toISOString(),
    status: 'new',
  };
  const orders = await getOrders();
  setStoredItem(STORAGE_KEYS.ORDERS, [newOrder, ...orders]);
  return newOrder;
}
🔑 Key Takeaways — Pro Architecture
  • Service functions are async and always return a Promise — use await
  • Components never call fetch() directly — services do that
  • The USE_MOCK_DATA flag lets you switch backend/frontend independently
  • Error handling is centralized in the service layer (not scattered in components)
  • This pattern is called Repository Pattern / Service Layer Pattern

localStorage Persistence & Lazy State Initialization

Pro
💾
localStorage + Lazy useState
Persist data across page refreshes — the cart survives browser reload!
Definition

localStorage is a browser API that stores key-value pairs permanently (until cleared). React state is lost on page reload — but by combining useState with localStorage, you get persistence. The lazy initializer pattern (useState(() => getFromStorage())) reads from localStorage only once on mount, avoiding redundant reads. SpideyCafe persists the cart, order list, and table number this way — refresh the page and your cart is still there!

src/services/storageService.js + src/context/OrderContext.jsx
storageService.js — safe localStorage wrapper JS 
// Safe wrappers that handle JSON parsing errors gracefully
export const STORAGE_KEYS = {
  CART:   'brew_bite_cart',
  ORDERS: 'brew_bite_orders',
  TABLE:  'brew_bite_current_table',
};

export function getStoredItem(key, defaultValue) {
  try {
    const item = window.localStorage.getItem(key);
    if (!item) return defaultValue;
    return JSON.parse(item);      // ← parse JSON string back to object
  } catch (error) {
    console.error(`Error reading "${key}" from localStorage`, error);
    return defaultValue;          // ← fail gracefully
  }
}

export function setStoredItem(key, value) {
  try {
    window.localStorage.setItem(key, JSON.stringify(value));  // ← serialize to JSON
  } catch (error) {
    console.error(error);
  }
}

// ── OrderContext.jsx — Lazy State Initialization ─────────────
// The function form of useState — runs ONCE to get initial value
const [cartItems, setCartItems] = useState(() => {
  return getStoredItem(STORAGE_KEYS.CART, []);  // ← read from localStorage on init
});
//                                 ↑
// Passing a FUNCTION to useState means:
// "call this function once to get the initial value"
// vs useState([]) which would just set an empty array always

// Sync cart to localStorage whenever it changes
useEffect(() => {
  setStoredItem(STORAGE_KEYS.CART, cartItems);
}, [cartItems]);
// Every time user adds/removes items → localStorage updates automatically
